# ໂຄງສ້າງລະບົບ (Architecture)

> ເອກະສານອອກແບບ. ຍັງບໍ່ມີໂຄດ; ລາຍລະອຽດຈະປັບຕາມການພັດທະນາຈິງ.

## 1. ພາບລວມ: 5 ຊັ້ນ

```
┌── ຊັ້ນ 1: ຂ່າວ ແລະ ສະພາບຕະຫຼາດ (Market Context) ─────────┐
│ ທຸກເຊົ້າ + ກ່ອນຂ່າວໃຫຍ່                                     │
│ AI ອ່ານປະຕິທິນເສດຖະກິດ, ຂ່າວ Fed, ເງິນເຟີ້, ພູມີລັດຖະສາດ       │
│ → ສະຫຼຸບພາສາລາວ + ຄະແນນຄວາມສ່ຽງ 0–100                      │
│ → ຂຽນ risk_control.json (ຄຳສັ່ງເບກໃຫ້ EA)                   │
└─────────────────────────────────────────────────────┘
                         ↓
┌── ຊັ້ນ 2: ບອດເທຣດ (EA ໃນ MT5) ─────────────────────────┐
│ Strategy modules (A, B, C, D) → ສັນຍານ                   │
│ Risk Manager (ກົດເຫຼັກ, AI ຍົກເລີກບໍ່ໄດ້)                  │
│ ອ່ານ risk_control.json (ຫຼຸດໄດ້ຢ່າງດຽວ, ເພີ່ມບໍ່ໄດ້)         │
└─────────────────────────────────────────────────────┘
                         ↓
┌── ຊັ້ນ 3: ບັນທຶກການເທຣດ (Trade Journal) ─────────────────┐
│ ທຸກໄມ້ + ສະພາບແວດລ້ອມຕອນເຂົ້າອໍເດີ → SQLite                │
└─────────────────────────────────────────────────────┘
                         ↓
┌── ຊັ້ນ 4: ວິເຄາະ ແລະ ຮຽນຮູ້ (Analysis) ──────────────────┐
│ 4a. ສະຖິຕິ + ML: ຊອກເງື່ອນໄຂທີ່ໄດ້ ຫຼື ເສຍ                  │
│ 4b. Claude API: ອະທິບາຍຕົ້ນເຫດ, ສະເໜີສົມມຸດຕິຖານໃໝ່         │
└─────────────────────────────────────────────────────┘
                         ↓
┌── ຊັ້ນ 5: ວົງຈອນປັບປຸງ (Improvement Loop) ───────────────┐
│ ສົມມຸດຕິຖານ → backtest ອັດຕະໂນມັດ → walk-forward           │
│ → ລາຍງານ Telegram → ມະນຸດອະນຸມັດ → ອັບເດດ EA               │
└─────────────────────────────────────────────────────┘
```

## 2. ການແບ່ງສ່ວນທາງເທັກນິກ

```
Windows PC / VPS
│
├── MT5 Terminal (Exness demo → FTMO)
│    └── EA (MQL5)
│         ├── ຂຽນ: MQL5/Files/journal/trades_*.csv  ──┐
│         ├── ຂຽນ: MQL5/Files/heartbeat.json         │
│         └── ອ່ານ: MQL5/Files/risk_control.json  ←──┐│
│                                                   ││
└── Python service                                  ││
     ├── journal_sync   ← ນຳເຂົ້າ CSV → SQLite  ←────┼┘
     ├── market_context → ຂ່າວ + Claude → risk_control.json
     ├── analysis       → ສະຖິຕິ, ML, Claude → ລາຍງານ
     ├── backtest       → ທົດສອບກົນລະຍຸດ + Monte Carlo FTMO
     └── telegram_bot   → ແຈ້ງເຕືອນ + ປຸ່ມອະນຸມັດ
```

**ຫຼັກການ:** EA ຕ້ອງເຮັດວຽກໄດ້ຄົບໂດຍບໍ່ມີ Python. ຖ້າ `risk_control.json` ບໍ່ມີ, ເກົ່າເກີນ 24 ຊົ່ວໂມງ, ຫຼື ອ່ານບໍ່ໄດ້, EA ຈະໃຊ້ຄ່າ default ທີ່ປອດໄພ ແລະ ແຈ້ງເຕືອນ.

ການສື່ສານຜ່ານໄຟລ໌ເລືອກເພາະງ່າຍ, ທົນທານ ແລະ debug ງ່າຍ. ຖ້າຕ້ອງການຄວາມໄວກວ່ານີ້ ຄ່ອຍປ່ຽນເປັນ socket ພາຍຫຼັງ.

## 3. Risk Manager (ຢູ່ໃນ EA)

| ກົດ | ຄ່າເລີ່ມຕົ້ນ | ໝາຍເຫດ |
|---|---|---|
| ຄວາມສ່ຽງຕໍ່ໄມ້ | 0.25–0.5% ຂອງ balance | ກຳນົດຈາກຕົວຈຳລອງການເສັງ |
| ເສຍສູງສຸດຕໍ່ມື້ (ລວມ floating) | 3% | FTMO ຈຳກັດ 5%; ເຮົາກັນໄວ້ 2% |
| ເສຍສູງສຸດລວມ | 7% → ຢຸດທັງໝົດ | FTMO ຈຳກັດ 10% |
| ຄວາມສ່ຽງເປີດພ້ອມກັນສູງສຸດ | 1.5% | ລວມທຸກກົນລະຍຸດ |
| ຈຳກັດຕາມ symbol | 1 ອໍເດີຕໍ່ກົນລະຍຸດຕໍ່ symbol | ກັນ over-exposure |
| ຊ່ວງຂ່າວແຮງ | ບໍ່ເປີດ 30 ນາທີກ່ອນ ຫາ 15 ນາທີຫຼັງ | ປັບໄດ້ຕາມກົນລະຍຸດ |
| ທຸກອໍເດີຕ້ອງມີ Stop Loss | ບັງຄັບ | ບໍ່ມີ SL = ບໍ່ສົ່ງອໍເດີ |
| AI risk multiplier | 0.0–1.0 | ຄ່າຫຼາຍກວ່າ 1.0 ຈະຖືກຕັດເປັນ 1.0 |
| Kill switch | ໄຟລ໌ ຫຼື ຄຳສັ່ງ Telegram | ປິດທຸກອໍເດີທັນທີ |

ມື້ໃໝ່ຄິດຕາມເວລາ server ຂອງ prop firm (FTMO ໃຊ້ເວລາ CE(S)T). ຕ້ອງກວດອີກເທື່ອກ່ອນເສັງ.

## 4. Trade Journal: ຂໍ້ມູນທີ່ບັນທຶກທຸກໄມ້

| ກຸ່ມ | ຟີລດ໌ |
|---|---|
| ພື້ນຖານ | ticket, strategy_id, symbol, direction, open/close time, entry/exit price, SL, TP, lot, profit, R-multiple, exit reason |
| ສະພາບຕະຫຼາດ | ATR (ທຽບກັບຄ່າສະເລ່ຍ), ທິດທາງແນວໂນ້ມ (MA ຫຼາຍ timeframe), spread, session, ມື້ໃນອາທິດ |
| ຂ່າວ | ນາທີຫາຂ່າວລະດັບສູງຄັ້ງຕໍ່ໄປ ຫຼື ຄັ້ງກ່ອນ, ຄະແນນຄວາມສ່ຽງປະຈຳວັນ |
| ຄຸນນະພາບການເຂົ້າ ແລະ ອອກ | MAE (ຕິດລົບສູງສຸດ), MFE (ບວກສູງສຸດ), slippage |
| AI (shadow) | ຄວາມເຫັນຂອງ AI ກ່ອນເຂົ້າ (ເຂົ້າ, ຂ້າມ ຫຼື ຫຼຸດ lot), ຄວາມໝັ້ນໃຈ, ເຫດຜົນ |
| Portfolio | ຈຳນວນອໍເດີທີ່ເປີດຢູ່, P&L ຂອງມື້ຕອນເຂົ້າ |

## 5. ຊັ້ນວິເຄາະ

**4a. ສະຖິຕິ + ML (ໃຫ້ຕົວເລກ):**
- ແບ່ງຜົນຕາມເງື່ອນໄຂ (session, ATR, trend, ຂ່າວ) → ຊອກກຸ່ມທີ່ເສຍຜິດປົກກະຕິ
- ກວດນ້ຳໜັກທາງສະຖິຕິ (ມີໄມ້ພໍບໍ່, ຕ່າງຈາກໂຊກແທ້ບໍ່)
- Meta-labeling: ໂມເດວ ML ປະເມີນໂອກາດສຳເລັດຂອງແຕ່ລະສັນຍານ (ໃຊ້ໃນ AI ລະດັບ 2)
- Regime detection: ແຍກສະພາບຕະຫຼາດ trend, range ແລະ high-volatility

**4b. Claude (ໃຫ້ຄວາມເຂົ້າໃຈ):**
- ອ່ານຜົນຈາກ 4a + ລາຍລະອຽດໄມ້ → ອະທິບາຍຕົ້ນເຫດເປັນພາສາລາວ
- ສະເໜີສົມມຸດຕິຖານທີ່ທົດສອບໄດ້ (ຕົວກອງ, ກົດໃໝ່)
- ຂຽນລາຍງານປະຈຳວັນ ແລະ ອາທິດ
- **ຂໍ້ຈຳກັດ:** Claude ບໍ່ປ່ຽນ EA ໂດຍກົງ. ທຸກຂໍ້ສະເໜີຕ້ອງຜ່ານ backtest + ມະນຸດອະນຸມັດ

## 5b. Multi-agent desk ແລະ ການປ່ຽນໂມເດວ AI

ຊັ້ນ AI ບໍ່ຜູກກັບ AI ຍີ່ຫໍ້ໃດ. ທຸກ agent ເອີ້ນຜ່ານ interface ດຽວກັນ, ສະນັ້ນປ່ຽນໂມເດວໄດ້ດ້ວຍການແກ້ config:

```toml
[ai.agents]
setup   = "anthropic:claude-..."   # ຕົວຢ່າງ; ຊື່ໂມເດວຕັ້ງໃນ config
context = "anthropic:claude-..."
exit    = "openai:gpt-..."
veto    = "anthropic:claude-..."
```

```
ສັນຍານຈາກ EA
   ↓
┌─ Setup Agent:    ຄຸນນະພາບຂອງ setup (ທຽບກັບ setup ທີ່ຄ້າຍກັນໃນ journal)
├─ Context Agent:  ຂ່າວ, ຄວາມຜັນຜວນ, liquidity, ຄະແນນຄວາມສ່ຽງຂອງມື້
├─ Exit Agent:     SL ແລະ TP ສົມເຫດສົມຜົນບໍ (ທຽບກັບ MAE/MFE ໃນອະດີດ)
└─ Veto Agent:     ສະຫຼຸບ → take | reduce | skip + ຄວາມໝັ້ນໃຈ + ເຫດຜົນ
   ↓
ບັນທຶກໃນ journal (ai_verdict, ai_confidence, ai_reason + ຊື່ໂມເດວ)
```

**ການແຂ່ງໂມເດວ:** ແລ່ນຫຼາຍໂມເດວກັບສັນຍານຊຸດດຽວກັນໃນ shadow mode. ຫຼັງ 100+ ໄມ້ ທຽບຜົນວ່າ "ຖ້າເຮັດຕາມໂມເດວນີ້" ຈະໄດ້ R ລວມ ແລະ drawdown ເທົ່າໃດ. ໂມເດວທີ່ດີທີ່ສຸດຈຶ່ງໄດ້ຂຶ້ນລະດັບອຳນາດ 1 ຫຼື 2.

**ຂໍ້ຈຳກັດ:** AI ໃຊ້ເວລາຕອບຫຼາຍວິນາທີ. ສະນັ້ນ desk ນີ້ເໝາະກັບກົນລະຍຸດ H1 ຫຼື D1, ບໍ່ເໝາະກັບ scalping. ຖ້າ API ລົ້ມ ຫຼື ຕອບຊ້າເກີນ timeout, EA ຈະເຮັດຕາມກົດປົກກະຕິ.

## 6. Backtest ແລະ ຕົວຈຳລອງການເສັງ

- **ຂໍ້ມູນ:** ດຶງຈາກ MT5 ດ້ວຍ Python package `MetaTrader5` (ຮອງຮັບ Windows ເທົ່ານັ້ນ)
- **ຕົ້ນທຶນການເທຣດ:** ຕ້ອງລວມ spread, commission, swap ແລະ slippage
- **ກັນ overfitting:**
  - ແບ່ງຂໍ້ມູນ in-sample ແລະ out-of-sample
  - Walk-forward
  - ໃຊ້ parameter ໜ້ອຍ
  - ກວດຄວາມໝັ້ນຄົງເມື່ອປ່ຽນ parameter ເລັກນ້ອຍ
- **Monte Carlo FTMO:** ສຸ່ມລຳດັບການເທຣດ 10,000 ເທື່ອ ພາຍໃຕ້ກົດເສັງ → ໄດ້ໂອກາດຜ່ານ, ເວລາສະເລ່ຍ ແລະ ລະດັບຄວາມສ່ຽງຕໍ່ໄມ້ທີ່ເໝາະສົມ
- **ຢືນຢັນ:** ທົດສອບຊ້ຳໃນ MT5 Strategy Tester (tick data)
